# Sportnis MVP Product Rules

## Status
- Version: draft-1
- Date: 2026-03-10
- Scope: MVP

## Core Principles
- MVP должен быть максимально простым в онбординге.
- Регистрация не должна требовать полного заполнения профиля.
- Пользователь может пользоваться системой с частично заполненным профилем.

## Guest Mode
- Гость может просматривать публичные анкеты и каталог без регистрации.
- Гость не может создавать, редактировать, очищать профиль и выполнять действия, требующие авторизации.

## Registration and Login
- Первичная регистрация: минимальный набор данных.
- Базовые поля регистрации: `email` (или `phone`), `password`, `username`, `whoAreYou` (`CONSUMER` или `PROVIDER`).
- После регистрации пользователь получает JWT и попадает в профиль выбранного типа.
- Логин: по `email/phone + password`.
- Logout: клиент удаляет токен; сервер в MVP не ведет blacklist токенов.

## Profile Model
- На регистрации создается один профиль (выбранного типа), не два.
- Второй профиль пользователь может создать позже вручную.
- В аккаунте может быть несколько профилей, но всегда один активный (`activeProfileId`).
- Переключение между профилями поддерживается.

## Profile Lifecycle
- Профиль нельзя удалять пользователю.
- Профиль можно очищать (reset до дефолтных значений).
- Аккаунт пользователя можно удалить целиком.

## Onboarding
- Регистрация и заполнение профиля разделены по этапам.
- После регистрации профиль может быть неполным.
- Система должна хранить состояние онбординга (например, `onboardingStep` или `profileCompleted`).

## Public Data Rules
- Публично доступны только данные профиля, разрешенные флагами приватности.
- Непубличные профили не должны быть доступны гостям.

## API Versioning
- `/api/v1/...` — версия внешнего API.
- Версии миграций БД живут отдельно (`V1`, `V2`, ...).

## Non-Goals for Current Stage
- Нет сложного RBAC/ACL сверх текущей модели ролей.
- Нет серверного logout blacklist (можно добавить позже).
- Нет принудительного completion профиля перед базовым использованием.
